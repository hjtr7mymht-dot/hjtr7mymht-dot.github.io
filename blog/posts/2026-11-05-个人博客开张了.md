折腾了一晚上，我的个人博客终于上线了，就在这个网站的 `/blog/` 下面。这篇文章说说为什么做，以及它是怎么跑起来的。

## 为什么还要一个博客

公众号是我的主要输出阵地，但它是租来的地。排版受限、随时可能改规则、文章的"数字产权"始终不完全在我手里。

我的想法很简单：**写过的东西，得有个自己的家。**

个人网站之前是单页结构——首页、关于、项目、联系方式，一页滑到底。它适合当名片，但不适合当内容载体。卡片上写的"每周 1-2 篇深度长文更新"，总得有个地方承接这些长文。

## 技术选型：能跑通最小闭环就行

我一直相信一句话：先跑通最小闭环，再谈规模化。这次的选型完全按这个原则来：

- **纯静态 HTML + CSS**，没有 React、没有 Next.js，双击都能打开
- **GitHub Pages 托管**，零成本，HTTPS 自带
- **一个 300 行的 Python 脚本**做静态生成，零第三方依赖
- 文章用 Markdown 写，`posts/` 目录下丢一个 `.md` 文件就行

生成脚本只做三件事：读 Markdown、套模板、输出 HTML。支持的语法是够用的子集——标题、列表、引用、代码块、加粗、链接，没有多余的花活。

```bash
cd blog
python3 build.py
git add . && git commit -m "博客更新" && git push
```

三行命令，一次发布。不需要 build 工具链，不需要 node_modules，换台电脑也能发文章。

## 和主页共用主题

博客跟主页用的是同一套设计变量：同一套颜色、同一个 Inter 字体、同一个圆角和阴影。最重要的是**主题状态共用 `localStorage` 的同一个 key**——你在主页切成暗色，点进博客也是暗色，不用再切一次。

这种"小细节"不难做，但省掉的那点割裂感很值。

## 以后会写什么

大概三类：

1. **AI 产品拆解** —— 不止说"这个好用"，要说清楚它为什么好用、怎么实现的
2. **Python 自动化实战** —— 我做的那些工具，踩过的坑和解法
3. **物联网 / 工业互联网实践** —— 专业相关，从设备接入到数据落地

不追热点，只写自己动手验证过的东西。能用代码验证的结论，不靠猜。

博客支持 RSS，想订阅的在页脚找 `RSS Feed` 就行。欢迎常来。
